# 명세: 렌탈 상세에 기기 시리얼, 렌탈 목록에 지금 시점

- 기능 브랜치: `claude/project-thread-nvbnsg` (contracts, rental_server)
- 날짜: 2026-11-03
- 요청: C(웹, WE1·WE3) → A(민서). 계약 1.0.0 고정 이후 **추가만** 하는 변경
- 관련 요구사항: FR-RNT-02(렌탈과 세 시점 상태), FR-USR-03(내 렌탈 목록)

## 배경

웹 렌탈 상세 화면은 기기 시리얼을 보여 주려고 `GET /devices/{deviceId}`를 한 번 더 부르고,
렌탈 목록은 행마다 지금 어느 시점(출고·수령·반납)인지 보이려고 상세를 행마다 불러야 한다.
CUSTOMER는 기기 API 권한이 없어 시리얼을 볼 길이 없다.

## 사용자 시나리오

1. 관리자가 렌탈 상세를 열면 기기 시리얼이 바로 보인다. (상세 응답 한 번)
2. 관리자·고객이 렌탈 목록을 열면 행마다 지금 시점 종류와 상태(예: 수령 · 진행 중)가 보인다. (목록 응답 한 번)
3. 아직 출고를 시작하지 않은 렌탈은 "시작 전"으로 보인다.

## 요구사항

- FR-1 `Rental`(상세·생성 응답)에 `serial`(string)을 더한다.
- FR-2 `RentalSummary`(목록 항목)에 `currentCheckpoint`(`Checkpoint` 또는 null)를 더한다.
  지금 시점 = 시작된 시점 중 가장 뒤(OUT → RCV → RET). 없으면 null.
- FR-3 두 필드는 스키마에서 선택(required에 넣지 않음)으로 둔다(1.0.0 고정 규칙: 선택 필드 추가만). rental-server는 항상 보낸다.
- FR-4 기존 필드·경로·코드 값은 바꾸지 않는다.

## 수용 기준

- 렌탈 상세 응답에 `serial`이 기기 시리얼과 같게 있다.
- 출고만 시작한 렌탈의 목록 항목 `currentCheckpoint.type`은 `OUT`, 출고 봉인 뒤 수령을 시작하면 `RCV`이다.
- 시점이 없는 렌탈의 `currentCheckpoint`는 null이다.
- 목록 한 페이지(최대 100건)를 읽을 때 렌탈마다 시점 쿼리를 따로 내지 않는다.
- `계약 검사` CI(yamllint·코드 생성본·redocly)가 통과한다.

## 범위 밖

- 목록을 시점으로 거르는 쿼리 파라미터(필요하면 다음에 추가)
- 상세에 기종 코드·이름 추가(요청 없음)
